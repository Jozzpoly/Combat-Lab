### Failures from an earlier source-distribution direction

- Attempted one-file offline \`file://\` HTML. The built bundle was ~3.56MB and contained inlined JS/CSS, but headless Chrome \`file://\` navigation was rejected by an administrator policy in one attempt. Serving the same single file over localhost also failed: normal HTML loaded but Rapier initialization did not finish. Instrumentation reached \`p10cBeforeWasm\` and never reached \`p10cAfterWasm\` in the classic packaging variant. **Exact root cause of that async init stall was not fully proven.** One-file HTML is **NOT a qualified working product**, should NOT be offered to Owner. Original experiments are available in Git history, and obsolete implementation files were cleaned from HEAD.
- Windows preflight mistakenly required >100KB in Vite entry script or >1MB of JS alone; actual Vite output splits JS (~410KB) and WASM into its own ~2.4MB binary. Corrected test to check real MIME/entry, actual source files and total asset bytes. Signed Node signature and OS smoke passed.
- These FAILs were used to choose a simpler, reproducible path. Do not reintroduce large one-file packaging as a default goal without real user need.
