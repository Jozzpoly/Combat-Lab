# RELATIONAL MANIFOLD R3 — Joint Afterstate Causal Kernel

**Date:** 2026-09-25  
**Status:** active hypothesis card; pre-implementation  
**Owner play:** not eligible  
**Source:** `JOINT_RELATIONAL_AFTERSTATE_AUDIT_2026-09-25.md`

## 0. Purpose

R0 proved local no-auto-neutral readiness.

R1 and R2 showed that local readiness can remain physically real while still failing to change the useful decision under pressure.

R3 asks a different mechanism question:

> **Can one ordinary material contact leave both participants in a jointly produced afterstate, so identical next intents are realized differently for both sides because of their shared history?**

This is not a combat organism.

R3 contains:

- two responsive bodies;
- one material tool per body;
- continuous segment/segment contact;
- simple GUIDE + COMMIT intent;
- no HP;
- no damage;
- no AI strategy;
- no bind mode;
- no terrain puzzle.

---

## 1. What counts as a relational manifold

Working definition:

> **a continuous material configuration jointly determined by two participants that changes both participants while it exists and leaves consequential physical state when it breaks.**

The relation may be encoded through:

- tool pose;
- tool velocity;
- relative tool geometry;
- body pose / velocity if contact physically transfers into bodies.

It must not be encoded through:

- bind token;
- parry success flag;
- grapple owner;
- vulnerability timer;
- hidden advantage state.

---

## 2. Intent surface

Each participant has the same compact control vocabulary.

### GUIDE

Bounded authority toward an intended tool direction.

GUIDE:

- keeps the tool manageable;
- remains finite;
- cannot teleport pose;
- cannot instantly erase shared contact state.

### COMMIT

Temporary extra authority toward captured intent.

COMMIT:

- starts from actual current tool pose/velocity;
- does not reset to canonical guard;
- keeps body locomotion live;
- does not home after capture.

No special input exists for "bind", "push blades", "win contact" or "break contact".

The relation must emerge from ordinary opposing GUIDE / COMMIT.

---

## 3. Contact law

Tools are finite material segments anchored to their bodies.

When segments intersect:

- contact point is derived from actual geometry;
- relative point velocity is derived from both tools;
- response is symmetric;
- both tool velocities may change;
- sustained contact is treated as one contact episode rather than repeated impact events.

The solver may dissipate energy.

It may not:

- declare a winner;
- cancel one action by priority;
- snap either tool to a authored pose;
- freeze either body.

---

## 4. Kernel histories

Start both participants from the same mirrored state.

Run one identical first interaction under matched ordinary intents.

### CONTACT history

Tool collision is enabled.

The two tools enter actual shared contact and later separate through ordinary motion.

### GHOST history

All inputs are identical, but tool/tool material response is disabled.

Tools pass through each other.

This is the primary causal control.

If CONTACT and GHOST histories remain equivalent:

> **R3 FAIL — no meaningful joint afterstate exists.**

---

## 5. Required shared-contact evidence

Before afterstate claims, CONTACT must demonstrate:

- at least one fresh energetic impact;
- a sustained contact episode lasting more than one simulation step;
- contact evolution determined by both tools;
- both participants' tool states changed;
- finite / deterministic behavior;
- contact ends through geometry, not a hidden timer.

A one-frame bounce is not enough.

A scripted "locked" interval is disallowed.

---

## 6. Break-state measurement

At the first stable separation after a genuine shared contact episode, record for both participants:

- tool angle;
- angular velocity;
- reach;
- radial velocity;
- body facing;
- body velocity;
- relative tool/body geometry.

Compare CONTACT against matched GHOST.

Required phenomenon:

> **both participants must carry measurable state differences produced by the shared contact.**

One-sided difference is insufficient.

---

## 7. Identical-next-intent experiment

After matched short interlude:

1. CONTACT and GHOST histories receive the same GUIDE intent for actor A;
2. same GUIDE intent for actor B;
3. both receive the same next COMMIT timing and direction;
4. no AI branch may inspect which history occurred.

Measure both realized next actions:

- path swept;
- time to intended line;
- maximum deviation;
- contact / no-contact outcome with a neutral fixture if needed;
- readiness start/end.

R3 requires:

> **the identical next intent of A differs across CONTACT/GHOST, and the identical next intent of B also differs.**

This is the key upgrade over R0.

---

## 8. INDEPENDENT RESET ablation

After the first shared contact breaks, run a matched ablation where each tool independently restores its own local canonical guide target using a competent physical spring.

Bodies are not frozen.

Question:

> **does local neutralization erase the joint tool-history effect much faster than ordinary GUIDE?**

Expected if R3 is real:

- ordinary no-reset CONTACT history preserves substantial divergence;
- independent reset collapses tool-readiness divergence;
- any remaining body-position/velocity divergence is reported separately and is not credited as tool-manifold readiness.

This isolates the same neutral-attractor failure seen in Terrarium.

---

## 9. One-side ownership falsifier

Run asymmetric intent after contact.

FAIL if:

- A can erase the relation instantly by ordinary aim while B cannot respond;
- one tool behaves like an authoritative controller and the other like a passive obstacle;
- the result is effectively local readiness plus a target.

Both sides must materially participate in the relation.

---

## 10. Physics-wrestling / noise falsifier

FAIL if:

- the contact normal jitters enough to dominate outcome;
- repeated overlap pumps energy;
- tiny starting perturbations create qualitatively unrelated results;
- useful state requires micromanaging contact;
- tools remain stuck indefinitely without an authored escape.

Required:

- deterministic replay;
- bounded energy;
- bounded contact duration under the tested intent;
- stable mirrored behavior.

---

## 11. Static-wall falsifier

FAIL if:

- value appears only because one body/tool is effectively immovable;
- the relation reduces to O1-style one-sided support;
- changing which side moves changes authority by implementation priority rather than physics.

Initial R3 therefore uses matched bodies/tools.

Mass/support asymmetry is deferred.

---

## 12. Passive-block falsifier

There is no damage in R3.

Persistent tool contact must not be interpreted as automatic defense.

R3 qualifies only:

- joint state;
- joint contact history;
- joint next-action consequence.

Threat/damage authority remains a later question.

---

## 13. Contact-duration sweep

Do not qualify from one magic setup.

Sweep at least three ordinary first-intent relations that create:

- brief contact;
- medium sustained contact;
- glancing / oblique contact.

Required:

- meaningful afterstate is not unique to one exact intersection point;
- one script does not solve the whole matrix;
- longer contact does not simply mean "more divergence" through numerical accumulation.

---

## 14. Tiny perturbation robustness

For each history, vary initial lateral/angle relation slightly.

The result need not be identical.

But it must remain interpretable:

- similar contact families produce similar afterstate families;
- no chaotic sign flips from microscopic perturbations.

If tiny changes dominate:

> **R3 FAIL as a usable substrate even if deterministic.**

---

## 15. Promotion gate

R3 becomes **joint-afterstate kernel qualified** only if all hold:

- real sustained shared contact occurs without bind state;
- both tools materially participate;
- CONTACT vs GHOST leaves meaningful state differences for both participants;
- identical next intents are realized differently for both participants;
- ordinary GUIDE preserves the effect long enough for a next decision;
- independent local reset collapses the tool-history effect much faster;
- no one-side ownership;
- no static-wall dependence;
- contact is stable / deterministic / bounded;
- effect survives a small contact-family sweep;
- effect survives tiny perturbations as an interpretable family;
- no HP/damage/AI strategy is required.

Owner eligibility remains:

> **NO.**

If R3 passes, the next question becomes whether such a shared relation creates an actual useful choice under minimal adversarial pressure.

If R3 fails, return to the relational-afterstate audit rather than tuning contact constants into a pass.

---

## Working invariant

> **A meaningful exchange should be able to leave both sides inside the same changed reality.**
